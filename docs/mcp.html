ModePick MCP Connector & Tool Reference

로컬 백엔드가 떠 있는 동안 같이 떠 있는 MCP 서버. Claude Desktop / Codex 같은 에이전트가 붙어서 페르소나 리소스를 읽고, 합성 작업을 돌리고, 인스타그램에 게시한다.

핵심 아이디어

  • FastAPI 백엔드와 같은 프로세스, 같은 lifecycle. 백엔드 죽으면 MCP 도 같이 죽음.
  • Transport: Streamable HTTP (stateless). 별도 데몬·인증·토큰 없이 로컬에서만 접근.
  • 리소스 생성은 사람이 직접 함 (UI). 에이전트는 조합·기획·실행만 한다.
  • 모든 게시 도구는 destructiveHint 가 붙어있어서 잘 만든 클라이언트는 자동 승인 안 함 — 사람 확인 후 실행.

붙이는 법

1. 백엔드 띄우기

cd backend
uv run uvicorn app.main:app --reload

기본 포트 8000. MCP 는 http://127.0.0.1:8000/mcp 에 떠 있다.

2. Claude Desktop

  1. Settings → Connectors → Add custom connector
  2. Name: modepick
  3. URL: http://127.0.0.1:8000/mcp
  4. 인증 없음 (로컬 전용)

3. Codex CLI

~/.codex/config.toml 에 추가:

[mcp_servers.modepick]
url = "http://127.0.0.1:8000/mcp"

Codex 버전이 HTTP MCP 미지원이면 stdio 브리지를 끼운다: 

[mcp_servers.modepick]
command = "npx"
args = ["-y", "mcp-remote", "http://127.0.0.1:8000/mcp"]
주의. 백엔드가 떠 있어야 MCP 도 떠 있다. 에이전트가 "서버에 못 붙는다" 고 하면 먼저 uvicorn 이 살아있는지 확인.

권장 워크플로우

  1. 탐색 — list_characters, list_wardrobe, list_world_locations, list_moods 호출해서 라이브러리 파악. 각 항목의 persona / notes / tags 필드를 읽고 어떤 조합이 어울릴지 판단.
  2. 제안 → 승인 — 사람한테 "이 조합으로 가도 되냐" 물어보고 OK 를 받은 다음에야 compose 호출.
  3. 합성 — compose_look (인물컷) 또는 compose_mood (사람 없는 무드컷) 호출 → job_id 받음 → get_compose_job 로 폴링.
  4. 확인 — status == "success" 되면 list_feed_posts(limit=10) 로 새 포스트 찾기. 사람한테 이미지 확인받기.
  5. 게시 — 승인 후 publish_single / publish_carousel / publish_stories 호출.
앞으로 리소스 (캐릭터/옷/세계관/무드) 만들 때 설명을 꼭 채워두기. 에이전트가 이걸 읽고 판단하기 때문에 비어있으면 좋은 조합을 못 만든다.

도구 목록

읽기 — Read

Tool설명
list_charactersread 모든 페르소나. persona dict (나이/스타일/외모 등) 포함.
list_wardroberead 옷 항목. category 로 필터링 가능 (hat, top, bottom, outerwear, dress, bag, shoes).
list_world_locationsread 세계관 장소 (집/카페/거리 등). notes 로 묘사.
list_moodsread 무드/조명 레퍼런스. tags 는 콤마 구분 자유 텍스트.
list_instagram_accountsread 게시 가능한 IG 계정 목록 (게시할 때 account_id 가 필요).
list_feed_postsread 생성된 피드 포스트 (최신순). only_unposted=true 로 미게시 드래프트만 조회.
get_compose_jobread 합성 작업 상태 폴링. status: pending / success / failed / missing.

합성 — Compose

Tool설명
compose_lookcompose 페르소나가 옷 입고 장면에 등장하는 인물컷.
주요 인자: character_id, wardrobe_slots (slot→item_id dict), location_id, mood_id, scene, count (1–4).
반환: {job_id, status: "pending"} — 폴링 필요.
compose_moodcompose 사람 없이 페르소나의 세계관을 보여주는 무드컷 (테이블 위 커피, 창가 디테일, 빈 거리 등).
주요 인자: character_id, location_id, mood_id, scene, count.
반환: {job_id, status: "pending"}.

게시 — Publish (destructive)

Tool설명
publish_singledestructive 피드 포스트 1개를 단일 이미지로 게시. caption / hashtags 인라인.
publish_carouseldestructive 피드 포스트 2–10개를 1개의 IG 캐러셀로 게시 (같은 캡션).
publish_storiesdestructive 피드 포스트 1–10개를 순차 스토리로 게시 (캡션/해시태그 없음). 부분 실패해도 이미 올라간 건 보존.

대화 예시

에이전트가 사람한테 던지는 전형적인 흐름:

너: "오늘 카페 무드로 피드 3장 짜줘"

에이전트: [list_characters, list_world_locations, list_moods 호출]
"활성 페르소나는 'Asakura Non' 이고, 카페 장소 'Morning Brew' 와
무드 'warm, golden hour, soft' 가 어울려보여요. 다음 조합 어때요?
  1. 인물컷: Non + 베이지 코트 + 카페 + 골든아워 무드
  2. 무드컷: 카페 테이블 위 라떼 + 같은 무드
  3. 무드컷: 카페 창가 빛 + 같은 무드
이대로 갈까요?"

너: "응"

에이전트: [compose_look + compose_mood × 2 호출 → 3개 job_id]
"세 작업 시작. 폴링 중..."

[get_compose_job × N 호출]
"세 개 다 success. list_feed_posts 로 결과 확인할게요."

[list_feed_posts(limit=10) 호출]
"3장 다 나왔어요. 어떤 형식으로 올릴까요? (단일 3개 / 캐러셀 1개 / 스토리 3개)"

너: "캐러셀로"

에이전트: "publish_carousel 호출하기 전에 마지막 확인: 어느 계정,
어떤 캡션으로 갈까요?"
